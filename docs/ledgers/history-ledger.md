ORIGINAL DESIGN: VERIFIED from f331b45 (a parentless root commit; a second, older root e8e59cb exists but the task scope starts here) at DirectInputForceFeedback~/DirectInputForceFeedback/DirectInputForceFeedback.{cpp,h} (1024+140 lines) and Plugin/DirectInputManager.cs (1051 lines; types live in Plugin/DirectInputTypes.cs). StartDirectInput installed a WH_CALLWNDPROC thread hook via SetWindowsHookExW(..., GetCurrentThreadId()) whose _WindowsHookCallback forwarded every WM_DEVICECHANGE wParam to _DeviceChangeCallback, then DirectInput8Create. StopDirectInput only Unacquire'd devices (never Release'd them or the DI instance, never unhooked). EnumerateDevices ran two EnumDevices passes (ATTACHEDONLY, then ATTACHEDONLY|FORCEFEEDBACK to flag FFBCapable); _EnumDevicesCallback new[]'d four char buffers per device (never freed) and dropped Fanatec duplicates (vendor 0x0EB7) by creating a temporary device and testing DIPROP_GUIDANDPATH for "&col02" in IsDuplicateHID. CreateDevice: CreateDevice -> SetDataFormat(c_dfDIJoystick2) -> SetCooperativeLevel(FindMainWindow(GetCurrentProcessId()) [EnumWindows, unowned+visible window of this PID], DISCL_EXCLUSIVE|DISCL_BACKGROUND) -> Acquire, leaking the COM device on any failure. GetDeviceState/GetDeviceStateRaw returned the raw HRESULT with no reacquire. CreateFFBEffect enumerated DIDOI_FFACTUATOR objects once per device (EnumObjects(..., DIEFT_ALL)), built one DIEFFECT spanning all FFB axes: DIEFF_CARTESIAN|DIEFF_OBJECTOFFSETS, INFINITE duration, gain DI_FFNOMINALMAX, rglDirection all 0, zeroed type params (periodic period 30000), unconditionally new'd DIRAMPFORCE+DIPERIODIC+DICUSTOMFORCE whatever the type (leak), then CreateEffect and immediately Start(1,0) and stored both DIEFFECT and LPDIRECTINPUTEFFECT. The CustomForce branch was a debugging stub: it appended to ffb_custom_debug.txt in the CWD, used cChannels=axisCount, cSamples=2, data {0,5000}, called CreateEffect and returned without Start and without storing the effect (so it could never be updated or destroyed). UpdateFFBEffect(guid, type, DICONDITION*) was the single update entry point: for idx in 0..cAxes it mapped DICONDITION fields into the type-specific struct (ConstantForce lMagnitude<-lPositiveCoefficient; periodic dwMagnitude/lOffset/dwPeriod<-lPositiveCoefficient/lOffset/dwPositiveSaturation; ramp lStart/lEnd<-pos/neg coefficient; conditions all six fields per axis) and called SetParameters(DIEP_TYPESPECIFICPARAMS); it indexed conditions[idx] up to cAxes, so a caller must supply cAxes entries. DestroyFFBEffect did Stop/Unload/Release and erased the map entries without freeing rgdwAxes/rglDirection/type params; StopAllFFBEffects called DestroyFFBEffect for all 12 types. String lists crossed the boundary as BSTR SAFEARRAYs. Manager: static DIManager over a Native P/Invoke class; Initialize = StartDirectInput + SetDeviceChangeCallback(OnDeviceChange) passed as a method group (delegate not rooted); OnDeviceChange -> 150 ms Debouncer -> ScanDevicesForChanges (re-enumerate, set-difference, raise OnDeviceAdded/OnDeviceRemoved, Destroy removed devices). Poll compared an MD5 of the marshaled FlatJoyState2. Every Update*Simple helper built a DICondition[1] and called Native.UpdateFFBEffect (so on a 2-FFB-axis device the native loop read past the array); UpdatePeriodicSimple and UpdateCustomForceSimple auto-created the effect on E_ABORT. UpdateEffect(DICondition[]) overwrote the caller's entries with new DICondition() before clamping, so it always sent zeros (VERIFIED original bug).
